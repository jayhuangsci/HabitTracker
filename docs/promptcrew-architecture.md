# 具体实现与复用决策

## 原代码如何复用

读取原 WPF、API、Core、存储和四个测试工程后，采用独立业务工程，保留旧训练应用。直接把 Workout 重命名为 Prompt 会保留不合适的组次、重量、日期规则，因此新领域模型独立实现。

| 原有代码 | 本次处理 |
| --- | --- |
| WPF ViewModelBase / RelayCommand / AsyncRelayCommand | 源码链接复用，继续使用 INotifyPropertyChanged 与命令可执行状态 |
| FlatTheme.xaml | 源码链接复用，增加独立中文资源与 DTO 展示模板，不改变原界面 |
| ASP.NET Core / EF Core / SQLite 基础 | 沿用技术栈与已使用包版本，独立 API 和 DbContext；新增项目密钥中间件与业务服务 |
| Workout / Habit / PlateStack 领域 | 保留给原应用，新业务不引用 |
| API 测试工厂与 WPF STA 测试方式 | 复用测试方法，使用全新临时数据库和真实请求 |
| OpenSilver / MAUI 客户端 | 原训练业务继续保留；本阶段没有声称已转换为 PromptCrew 移动端 |

## 数据写入的边界

`PromptCrew.Core` 使用 C# records 表达输入、快照和响应。Core 不知道 SQLite、HTTP 或 WPF。共享客户端把 API 错误转成带状态码和业务 code 的异常；桌面与命令行使用同一契约和认证逻辑。

每轮输入只有创建接口。父节点和输入修订目标的数据库外键包含 ProjectId / ChainId，员工及引用外键也包含 ProjectId。父节点只能指向已经存在的同链记录，创建后不能修改，因此正常 API 不能产生环。上下文读取仍保留重复节点检测，处理被外部工具破坏的数据库。

跨链关系使用 RoundReference，保持任务链单父树。Graph 返回父节点、引用与修订目标，桌面按父节点构造树，引用作为记录信息展示。

## 并发与幂等怎样配合

轮次创建为一次 EF SaveChanges 事务：新增记录、标签和引用，同时递增任务链 NextNumber 与 Version。SQLite 唯一约束保护链内序号和项目内请求 ID。并发失败时有限重试，重读当前链后分配序号，避免丢记录或重复编号。

追加输出需要轮次 ExpectedVersion，更新轮次状态/版本并插入 RoundResult 在同一事务提交。Guid 预分配的结果实体显式标为 Added，避免被 EF 误判为对现有结果更新。多个 Agent 使用同一旧版本时，一方成功，另一方得到 409，可以读回并追加合并版本。

请求 ID 去重先于当前工作区状态与员工版本校验，所以已成功请求的原样重放在角色改名或任务关闭后仍可返回原记录。请求指纹包含目标路径与规范化业务输入；同 ID 用于不同正文或其他目标返回冲突。结果请求也保留自己的指纹与唯一约束。

Agent 从 Context 读取员工定义版本，保存时再匹配；通过后将当时名字、职责、基础提示词和 Skills 写入独立 JSON 快照，后续员工编辑不会改变历史。

## 桌面断线恢复

编辑草稿按服务地址与任务链隔离，输出草稿再按记录 ID 保存。JSON 写入同目录临时文件后替换，降低写入中断造成半个文件的风险。无法读取旧文件时保留原文件，恢复到新文件。

提交前先把完整载荷和请求 UUID 写盘；写盘失败不发请求。网络中断后锁定对应载荷，提供同请求重试或状态查询。关闭和重启仍能找到原 ID。服务已经保存但响应丢失的场景在真实 WPF 工作流测试中使用故障处理器验证。

业务记录由 API 持久化；草稿文件供本机单窗口使用，不提供多窗口并发合并或离线 API 查询。

## 上下文与时间

祖先读取从选定父节点向上走，反转为根到父节点，再合并祖先显式引用与本轮拟引用。兄弟分支只有被明确引用才进入上下文。只解析一层引用，避免间接关系无限扩张。输出保留各版本，编译上下文默认使用每轮最新输出；历史输出仍在 DTO 中可查。

保存时间由注入的 TimeProvider 在服务端生成，持久化 UTC，读取 DTO 明确 UTC Kind，桌面最后才转本地时间。时间用于展示与检索排序；链内编号负责业务顺序，不靠多台 Agent 的本地时钟决定交接顺序。本产品没有复用训练业务的休息计时器。

## 存储与规模限制

PromptCrew 的数据目录从独立配置解析，默认是 LocalAppData/PromptCrew/personal。演示另建目录；没有对旧训练数据库执行迁移。迁移可由设计时 DbContextFactory 生成和检查，运行时启动会应用已有迁移。

搜索是 SQLite Contains 过滤，当前不接全文搜索服务。读取轮次及其历史/标签/引用采用单查询以获得一致记录视图；历史与引用很多时联表行数会增加。当前适合本机团队记录，后续可通过分页结果历史、FTS 和独立查询投影改善大库性能。当前界面搜索最多载入 200 轮；比较载入 200 条候选，并始终包含当前节点，API 可继续分页。上下文超过 256 个祖先或 500,000 字符会返回可解释错误。
